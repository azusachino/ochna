# v0.3 Acceptance — Kubernetes Corpus Benchmark

This experiment runs the frozen `docs/v0.3-contract.md` corpus-benchmark row
for Kubernetes: PR 139848 watch-cache tests, plus the `GetList` common-name
stress case for `impact`. It follows the required contract procedure —
archive the pinned commit into a disposable temp directory, `ochna init`
there, never touch the `clones/kubernetes` submodule.

## `GetList` common-name stress case (`ochna impact`)

### Bare name, default direction=callers, as specified

```bash
ochna impact GetList --direction callers --json   # 0.05s wall
```

```json
{
  "ok": false,
  "next_action": "narrow the query",
  "truncated": false,
  "data": { "root": null, "nodes": [], "edges": [], "unresolved_boundaries": [] },
  "warnings": [
    { "code": "ambiguous_symbol",
      "message": "symbol 'GetList' matches 9 indexed definitions; use --in or an ID/qualified name" }
  ]
}
```

`ochna search GetList` confirms exactly 9 exact-name matches across the
corpus (`store::GetList`, `Cacher::GetList`, `corruptObjectDeleter::GetList`,
`StorageInjectingListErrors::GetList`, `fakeStorage::GetList`,
`CacheDelegator::GetList`, `MockStorage::GetList`,
`storageWithCounter::GetList`, `DryRunnableStorage::GetList`), plus
`getList`/`BenchmarkStore_GetList`/`BenchmarkCacher_GetList` as separate
distinct names. `impact` refuses to pick one arbitrarily and refuses to
traverse the union of all nine — it reports `root: null`, `ok: false`, and
`next_action: "narrow the query"` immediately. This is the strongest form
of "does not silently explode into unbounded common-name fanout": rather
than capping mid-traversal, it declines to guess at all.

### Disambiguated by qualified name (the PR-relevant symbol)

```bash
ochna impact "CacheDelegator::GetList" --direction callers --json   # 0.17s wall
```

Result: `ok: true`, `truncated: false`, root resolved, **7 nodes, 7 edges,
8 paths, 7 affected_tests, 134 unresolved_boundaries** (99 ambiguous_target,
35 missing_target), all edges `resolution_kind: "package"` / `confidence: 80`.
The 7 affected tests are all in `cacher_whitebox_test.go`, including
`TestMatchExactResourceVersionFallback` — the exact test this PR rewrote to
exercise `CacheDelegator.GetList` directly, confirming the traversal
correctly reconnects the PR's changed test to the production symbol it now
calls. Under the default depth 2 / limit 50 budget, this real-world query
lands far under caps (7 of 200 nodes) — no truncation needed at this radius.

### Forcing the budget ceiling (depth 5, min-confidence 0, limit 200, direction both)

To confirm the truncation mechanism actually engages rather than just being
theoretical, three other `GetList` candidates were run at the contract's
maxima:

| Symbol | ok | truncated | nodes | edges | unresolved_boundaries |
| --- | --- | --- | --- | --- | --- |
| `store::GetList` | true | **true** | 200 (cap) | 284 | 400 (cap) |
| `corruptObjectDeleter::GetList` | true | **true** | 200 (cap) | 239 | 400 (cap) |
| `DryRunnableStorage::GetList` | true | false | 0 | 0 | 0 |

`store::GetList` and `corruptObjectDeleter::GetList` both hit the 200-node
budget exactly and correctly set `truncated: true`; `unresolved_boundaries`
also capped at exactly 400 in both cases, matching the edge-budget maximum
in the contract. Confidence remained honestly labelled throughout (no edge
silently upgraded past its resolution tier).

**Required evidence #2 — PASS.** The common-name traversal never explodes
unbounded: the ambiguous bare name refuses to guess, and once disambiguated,
a high-fanout root hits the exact 200-node/400-boundary ceiling and reports
`truncated: true` honestly rather than printing partial results as if
complete.

## `rg` comparison for the same common name

```bash
time rg -n "GetList" --type go .   # 0.71s wall, in the temp corpus tree
```

223 literal matches across 60 files, with zero confidence/resolution
labeling and no distinction between definitions, call sites, comments, or
substrings — e.g. `GetListMeta`, `GetListRestrictions`, and a code comment
(`// Cacher.GetList defines this for logic to decide...`) all appear
alongside real call sites because `rg -n "GetList"` matches as a substring.
A human using `rg` alone would have to manually triage all 223 lines across
60 files to separate real call edges from unrelated identifiers and prose.
`ochna impact "CacheDelegator::GetList" --direction callers --json` instead
returns exactly 7 confidence-labelled call edges plus 134 explicitly-flagged
unresolved boundaries — a fraction of the manual-filtering burden, at the
cost of requiring the caller to disambiguate the root symbol first (which
`ochna` itself prompts for when ambiguous).
